# よこずらしニュース ウィジェット 仕様書・実装指示書

2026-11-14 時点。もとの文書は https://claude.ai/artifact/6KtDaBj3bSbTKU3TTwbwxs 、デザインは https://claude.ai/artifact/UGAWsy1SdMZknN4PjQHnoE （Main がA案、Digits が数字見本）。実装を始めたら、このファイルを正本として書き換えていく。

## 概要

Androidのホーム画面に置く4×2のウィジェットを作る。今日の日付、現在地の天気、話題のニュース1本を表示し、ニュースの見出しは帯の中を右から左へ流れる。よこドーロタイマーに続く「よこ」シリーズの第2作。

ウィジェットは単体では配布できないので、Androidアプリを1つ作り、その中にウィジェットを入れる。アプリ本体は設定画面1枚だけの最小構成にする。位置情報の許可はアプリの画面からしか求められないため、この画面は省けない。

決定済みのこと:

- レイアウトはA案「ニュースデスク」
- 白衣のキャラを右に、よこずらしをニュースの帯の左上の縁に置く
- 日付の数字だけ手描き数字（タイマーと同じ素材）。4と5は「よこ」の語呂で黒塗り、ほかは中抜き
- 「月」「日」、曜日、気温、天気の文字はフォントのまま
- 帯の塗りは枠線とぴったり重ねる（横ずれなし）
- ニュースは配信フィード（RSS）から取り、見出しをそのまま流す。AIでの要約はしない
- 配布は依頼者自身の端末だけ。Google Play には出さない
- ソースコードはこのリポジトリの `news-widget/` に置く
- ニュースのフィードは Google ニュース（日本のトップニュース）のRSS
- 天気APIは Open-Meteo

## 仕様書 1: 画面

ウィジェットは5×3マスが標準で、大きさは変えられる（最小は4×2程度）。白地、角丸は端末の標準値に従う。下の表の寸法は基準寸法380×180dpでの値。実際の大きさはホーム画面のマス目で変わり、依頼者の端末では4×2が約250×172dp、5×3が約315×260dpになる。そのため左上・右下・下端への寄せで配置し、日付の拡大率とキャラの大きさは `WidgetLayout` が実際の大きさから決める（Android 12以上）。4×2では天気・地名の文字が省略表示になる。

| 要素 | 位置と大きさ（dp） | 見た目 |
| --- | --- | --- |
| 日付 | 左20・上10。数字の高さ32 | 手描き数字の画像。「月」「日」は15spの太字、数字の下端にそろえる |
| 曜日 | 日付のすぐ下 | 「金曜日」の形、13sp太字、マゼンタ #C8387A |
| 天気 | 曜日の下にアイコン24と気温22sp太字。「晴れ・地名」は曜日の右、11sp #5A5A5A | 実機のウィジェットは幅が約285dpしかなく、気温の右に置くとタブレットに重なったため、曜日の行へ移した |
| 白衣のキャラ | 右下寄せ。画像262×198、左156・上−8 | 帯の後ろに立つ。タブレットが日付側を向く |
| ニュースの帯 | 左10・右16・下8、高さ48 | 塗りティール #72CFCB、枠線2 #141414、角丸約16（手描き風に少し不ぞろい） |
| 「話題」ラベル | 帯の左端 | 黒地に白文字11sp太字、角丸 |
| 流れる文字 | ラベルとボタンの間 | 15sp、黒 #141414、1行、右から左へ流れる |
| 別のニュースボタン | 帯の右端、44×44 | シャッフルの線アイコン20 |
| よこずらし | 帯の左上の縁。枠36×36、左14（本体は高さ約18） | 足元が帯の上辺に少し重なる。72では目立ちすぎたので半分にした |

文字のフォントは、日付まわりと天気が Zen Maru Gothic、流れる文字が端末標準フォント。ウィジェットの文字部品は独自フォントを使えないため、日付と天気のブロックは1枚の画像として描く。

## 仕様書 2: ふるまい

表示する3つの情報は、それぞれ別の間隔で更新する。取得に失敗したときは、最後に取れた内容をそのまま出し続ける。

| 情報 | データの出どころ | 更新のタイミング | 一度も取れていないとき |
| --- | --- | --- | --- |
| 日付・曜日 | 端末の時計 | 0時ちょうど、時刻やタイムゾーンの変更時 | 該当なし（常に出せる） |
| 天気・気温 | Open-Meteo | 約1時間ごと | アイコンなし、「--°」 |
| 地名 | 端末の位置情報（おおよその位置）から市区町村名 | 天気と同時 | 「現在地」と表示 |
| ニュース | Google ニュース（日本のトップニュース）のRSS | 約30分ごとに一覧を取り直す | 「ニュースを取得できませんでした」を流さずに表示 |

ニュースの選び方:

- 取得した一覧（20件程度）を端末に保存し、その中から1件をランダムに表示する
- 一覧を取り直すたびに、表示する1件も選び直す
- 一度表示したものは、一覧を一巡するまで選ばない
- 流す文面は「見出し ― 出典名」。見出しをそのまま流し、要約は作らない

タップしたとき:

| タップする場所 | 起きること |
| --- | --- |
| ニュースの帯（ラベルと流れる文字） | その記事の元ページをブラウザで開く |
| 別のニュースボタン | 保存済みの一覧から別の1件に切り替える（通信しない） |
| それ以外（日付、天気、キャラ） | アプリの設定画面を開く |

動き:

- 流れる文字は止まらず繰り返す。速さは毎秒40dp（`tools/make_belts.py` の SPEED）
- よこずらしは9コマの横のびアニメを繰り返す。常時ループは電池を使うので、実機で消費を見て「常時」「ニュース切り替え時だけ」「静止」のどれにするか決める（未決事項）

## 仕様書 3: アプリ本体

アプリ本体は設定画面1枚だけで、役割は「位置情報の許可をもらう」と「ウィジェットの置き方を案内する」の2つ。

設定画面に置くもの:

- 位置情報の許可の状態と、許可を求めるボタン
- 「いま更新」ボタン（天気とニュースをすぐ取り直す）
- 最後に更新できた時刻（天気、ニュースそれぞれ）
- 「ホーム画面にウィジェットを追加」ボタン（対応するランチャーのみ）
- 天気データとニュースの出典の表記

位置情報の扱い:

- 求めるのは「おおよその位置」だけ。天気にはそれで足りる
- 初版は、アプリを開いたときに位置を取得して保存し、天気の更新にはその保存した位置を使う
- 移動しても自動で追いかけるには「常に許可」が要る。初版では求めない（未決事項）
- 許可がないとき、ウィジェットの天気欄は「位置情報を許可」と表示し、タップで設定画面を開く
- 位置は天気APIへの問い合わせにだけ使い、ほかには送らない

対応するAndroidは8.0以上とする。

## 実装指示書

最初に、流れる文字とよこずらしのアニメが実機のホーム画面で動くかを確かめてから、残りを作る。この2つはウィジェットの制約にいちばん当たりやすく、動かなければ画面の作り方が変わる。

### 技術構成

| 項目 | 使うもの | 理由 |
| --- | --- | --- |
| 言語・ビルド | Java、Gradleなし、`build.sh`（aapt2・javac・d8）、minSdk 26、外部ライブラリなし | よこドーロタイマー（`../pomodoro-timer`）と同じ作りにそろえ、同じ環境でビルドできるようにする |
| パッケージ名 | `app.yokozurashi.news`（仮） | タイマーが `app.yokozurashi.pomodoro` |
| ウィジェット | AppWidgetProvider と RemoteViews（XMLレイアウト） | タイマーと同じ。流れる文字もこの方式でしか出せない |
| 流れる文字 | ViewFlipper のアニメで動かす「ベルト」（`NewsBelt`、`tools/make_belts.py`） | TextView の marquee は実機でいったん流れたが、フォーカスを失うと止まり、ウィジェットからは戻せなかった |
| よこずらしのアニメ | まず ViewFlipper の自動送りを試す。だめならタイマーの `WidgetAnimHelper` と同じ、AlarmManager で1秒ごとにコマ画像を差し替える方式 | 後者はタイマーで動作実績がある。前者は動けばなめらか |
| 日付と天気のブロック | Canvas で Bitmap に描いて ImageView に渡す | 独自フォントと手描き数字を正確に並べるため |
| 定期更新 | JobScheduler（天気1時間、ニュース30分） | Android標準の機能だけで済み、再起動後も続く |
| 0時の日付更新 | AlarmManager と、時刻・タイムゾーン変更の受信 | JobScheduler は時刻を指定できない |
| 通信と解析 | HttpURLConnection、XmlPullParser、org.json | Android標準の機能だけで済む |
| 保存 | SharedPreferences（位置、天気、ニュース一覧、表示済みの印） | タイマーと同じ。データが小さい |
| 位置と地名 | LocationManager（おおよその位置）、Geocoder で市区町村名 | 天気には粗い位置で足りる |

### 作る順番

1. **検証用の最小ウィジェットを作る。** 中身は、固定の長い文を流す TextView と、よこずらし9コマの ViewFlipper だけ。
    - TextView は `singleLine`、`ellipsize="marquee"`、`marqueeRepeatLimit="marquee_forever"`、`focusable`、`focusableInTouchMode` を指定し、子要素に `<requestFocus/>` を入れる。
    - 確かめること: 文字が流れ続けるか。流れている文字をタップして PendingIntent が効くか。ホーム画面を切り替えて戻っても流れが止まらないか。端末標準のランチャーと、もう1種類のランチャーで見る。
    - ViewFlipper は `autoStart="true"`、`flipInterval="40"`。確かめること: コマが送られるか。1時間置いたときの電池消費。
2. **検証結果を報告して、進め方を確定する。** 動かなかった場合の代替は次のとおり。どちらを採るかは依頼者に確認してから決める。
    - 文字が流れない: 見出しを16文字前後に区切り、ViewFlipper で右から入って左へ出る横スライドで順に見せる。
    - アニメが重い、または電池を使いすぎる: タイマーと同じ、AlarmManager で1秒ごとにコマを差し替える方式にするか、静止画1枚にする。
3. **素材を整える。** 手描き数字はタイマーの透過PNG（num_0〜num_9）をそのまま使う。よこずらしは今回のGIFを9枚の透過PNGに分ける。Zen Maru Gothic（SIL Open Font License）をアプリに同梱する。
4. **レイアウトを仕様書1のとおりに組む。** データは固定値のままでよい。ウィジェット定義は `targetCellWidth="5"`、`targetCellHeight="3"`、`updatePeriodMillis="0"`、縦横ともサイズ変更できる。
5. **日付を入れる。** 日付と天気のブロックを Bitmap に描く処理を作り、0時と時刻変更で描き直す。月と日は1桁と2桁の両方を、4と5を含む日付で確かめる。
6. **天気を入れる。** 設定画面で位置の許可を取り、位置を保存する。天気APIから現在の気温と天気の種類を取り、アイコンと文言に対応づける。
7. **ニュースを入れる。** フィードを取得して一覧を保存し、ランダムに1件を選んで流す。流すのは見出しと出典名。使うフィードは候補を依頼者に見せて承認をもらい、取得部分は差し替えられる形に分けておく。
8. **タップをつなぐ。** 帯は記事のURLを開く、ボタンは別の1件に切り替える、それ以外は設定画面を開く。PendingIntent は `FLAG_IMMUTABLE` を付ける。
9. **設定画面と、取得できないときの表示を仕上げる。** 仕様書2と3の「取れていないとき」「許可がないとき」をすべて実機で出して確かめる。

### 決まりごと

- 「未決事項」にあることは、仮置きで進めてよいが、勝手に確定させない。後から差し替えられる作りにする。
- APIキーや個人情報をソースコードに書かない。位置は天気API以外に送らない。
- Bitmap はウィジェットの実寸（AppWidgetOptions の値）に合わせて作る。RemoteViews に渡せる画像の合計サイズには上限がある。
- キャラ、よこずらし、手描き数字の絵そのものには手を加えない。許される加工は、余白の切り落とし、背景の透過、拡大縮小だけ。
