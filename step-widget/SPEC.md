# よこずらしの旅 ウィジェット 仕様書

2026-11-15 時点。「よこ」シリーズの第3作。名前とパッケージ名（`app.yokozurashi.steps`）は仮。実装と一緒に、このファイルを正本として書き換えていく。

## 概要

歩数を「きょう何歩」ではなく、旅を始めてからの**累計の距離**として見せるウィジェット。歩いたぶんだけ、よこずらしが日本を西の端（与那国島）から東の端（納沙布岬）へ進む。通った土地ごとに名物があり、よこずらしはそれをずらしながら次の土地へ向かう（那覇にいるあいだは「シーサーをずらしています」）。

ほかの歩数計やスマートウォッチと役割が重ならないよう、目標歩数、消費カロリー、グラフ、通知は入れない。

見本は `assets/preview.png`（`tools/preview.py` が作る。実機の描画そのものではない）。

## 仕様書 1: 画面

ウィジェットは4×2マスが標準で、大きさは変えられる。白地。寸法は基準寸法250×172dpでの値で、実際の大きさに合わせて全体を拡大・縮小する（0.8〜1.8倍）。横の余りは帯と線が伸びて埋め、縦の余りは帯の上下に半分ずつ入る。

| 要素 | 位置と大きさ（dp） | 見た目 |
| --- | --- | --- |
| いまの場所 | 左16・上の行 | 「沖縄県 那覇」の形、13sp太字、マゼンタ #C8387A |
| 読み取りの時刻 | 上の行の右端 | 最後に歩数を読めた時刻「12:34」、10sp、灰 #5A5A5A。2周目からは「2周目 12:34」 |
| 累計の距離 | 左16・上32。数字の高さ32 | kmの整数部は手描き数字（タイマーと同じ素材。4と5は黒塗り）。小数1桁と「km」は15spのフォント |
| きょうの歩数 | 右端、距離と同じ行 | 「きょう」10sp灰の下に「6,543歩」16sp |
| 帯 | 左右10・上74、高さ34 | 塗りティール #72CFCB、枠線2 #141414、角丸14。文は「シーサーをずらしています」14sp太字。長ければ12sp、それでも入らなければ末尾を省略 |
| 道のりの線 | 左右26、下端から26 | 左端の黒丸がいまの地点、右端の白丸が次の地点。進んだぶんを太いティールで塗る |
| よこずらし | 線の上、進んだ割合の位置。枠60×60（本体は高さ約25） | 9コマの横のびアニメ。足元が線に乗る |
| 線の下の文字 | 下端 | 左に地点の名前、右に「読谷まで あと11.5km」。10.5sp灰 |

文字のフォントは Zen Maru Gothic。ウィジェットの文字部品は独自フォントを使えないため、よこずらし以外は1枚の画像として描く（`Panel`）。よこずらしだけは、コマ送りの部品を画像の上に重ねる。

タップしたとき:

| タップする場所 | 起きること |
| --- | --- |
| 上半分 | アプリの画面を開く |
| 下半分 | その場で歩数を読み直す（歩数の利用が未許可のときは、アプリの画面を開く） |

帯に出す文:

| 状態 | 文 |
| --- | --- |
| ふつう | 「（名物）をずらしています」 |
| ゴールに着いてから次の周回まで | 「ゴール！ 日の出をずらしています」 |
| 歩数の利用が未許可 | 「タップして歩数の利用を許可」 |
| 端末に歩数センサーがない | 「歩数センサーがありません」 |

## 仕様書 2: 旅のしくみ

- 距離は「累計の歩数 × 歩幅」。歩幅は標準70cm、アプリの画面で40〜100cmの範囲を5cmきざみで変えられる。歩幅を変えると、これまでの距離も計算し直す
- 道すじは `tools/route.csv` の145地点。47都道府県をすべて通る。区間の距離は、となり合う2地点の直線距離
- ゴールの納沙布岬まで8,333km。区間は平均58km（最短11km、最長287km）。1日8,000歩（5.6km）なら、名物が変わるのは平均で10日に1回、ゴールまで約4年
- ある地点に着いてから次の地点に着くまで、その地点の名物をずらしている扱いにする
- ゴールに着いたあとは、20km進むと与那国島に戻って2周目が始まる。累計の距離は増えつづける
- 旅の出発は、はじめて歩数を読めたとき。それより前の歩数は数えない

名物は、食べもの・生きもの・建物・景色を取りまぜた（「琵琶湖をずらしています」「富士山をずらしています」など）。商品名は避け、一般の呼び名にした。全部の一覧は `tools/make_route.py` を実行すると出る。

## 仕様書 3: 歩数の数え方

端末の歩数センサー（TYPE_STEP_COUNTER）を使う。このセンサーは端末が自分で数えつづけていて、値は「端末を起動してからの累計」になっている。そのためアプリは常駐せず、ときどき値を1つ読んで、前に読んだ値との差を足す。読むのがときどきでも、起動中に歩いたぶんは取りこぼさない。

| 読むとき | しくみ |
| --- | --- |
| 約15分ごと | JobScheduler（`StepJob`）。再起動のあとも続く |
| ウィジェットの下半分をタップしたとき | `StepWidgetProvider` |
| アプリの画面を開いたとき、「いま読み直す」を押したとき | `MainActivity` |
| 0時、時刻の変更、再起動、アプリの更新のあと | `DayAlarm`、`SystemEventReceiver` |

- 「きょうの歩数」は、読んだ時点の日付に足す。0時をまたいで読んだぶん（最大で15分ぶんほど）は新しい日に入る
- 再起動するとセンサーが0に戻る。起動回数が変わっていたら、センサーの値をそのまま足す。最後に読んでから電源を切るまでのぶんは数えられない
- 必要な許可は「身体活動」（Android 10以上）。アプリの画面から求める
- 歩数は端末の中だけに保存し、通信はしない（インターネットの権限を持たない）

## 仕様書 4: アプリ本体

画面は1枚。置くもの:

- 歩数の利用の許可の状態と、許可を求めるボタン
- 旅のようす（いまの場所、ずらしているもの、次の地点までの残り、累計の距離と歩数、きょうの歩数、出発の日時）と「いま読み直す」ボタン
- 歩幅の設定（−5cm・+5cm）
- 「ホーム画面にウィジェットを追加」ボタン
- これまでにずらしたもの（通過した地点の名物を、新しい順に）
- 「旅をやり直す」ボタン（確認のうえ、累計を0に戻す）

確認用のしかけ: 題名「よこずらしの旅」を長押しすると、30km進む。歩かなくても、地点の切り替わりや帯の文の長さを実機で見られる。「旅をやり直す」で消える。

## 技術構成

よこずらしニュース（`../news-widget`）と同じ作り。Java、Gradleなし、`build.sh`、minSdk 26、外部ライブラリなし。

| ファイル | 役割 |
| --- | --- |
| `StepReader` | 歩数センサーを1回読む。4秒待って値が来なければあきらめる |
| `StepStore` | 歩数の帳簿（累計、きょう、歩幅）。SharedPreferences |
| `Route` | 道すじの表。`tools/make_route.py` が `tools/route.csv` から作る |
| `Journey` | 距離から、いまの地点・名物・次の地点までの残りを割り出す |
| `Panel` | ウィジェットの絵を1枚の画像に描く |
| `StepWidgetProvider` | ウィジェット。よこずらしの位置は、枠の余白（padding）で決める |
| `StepJob`、`DayAlarm`、`SystemEventReceiver` | 読むきっかけ |
| `MainActivity` | アプリの画面 |

素材（手描き数字、よこずらし9コマ、Zen Maru Gothic）はニュースウィジェットのものを写した。絵そのものには手を加えていない。

## 進み具合

0.1（2026-11-15）で一式を作った。クラウドでビルドが通ることと、`Journey` の計算（地点の境目、ゴール、2周目）は確かめた。実機ではまだ何も確かめていない。

実機でまず確かめること（うまくいかなければ作りを変える）:

- [ ] 画面を消したままでも、約15分ごとの読み取りで歩数が進むか（ウィジェット右上の時刻が進むか）。Androidは裏で動くアプリにセンサーの値を渡さないことがあり、ここがいちばん当たりやすい。だめなら、読むきっかけをタップとアプリを開いたときだけにするか、常駐の通知を出して読む方式にする
- [ ] ウィジェットの下半分のタップで歩数が読み直されるか
- [ ] よこずらしが線の上の正しい位置に、足元を線に乗せて出るか（4×2と、大きさを変えたとき）
- [ ] 文字や数字の配置が見本（`assets/preview.png`）と合っているか
- [ ] 題名の長押しで進めたとき、地名と帯の文が切り替わるか
- [ ] 0時に「きょうの歩数」が0に戻るか
- [ ] 再起動のあとも、操作なしで歩数が進むか
