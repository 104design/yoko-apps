# よこめぐり ウィジェット 仕様書

2026-11-15 時点。「よこ」シリーズの第3作。名前は「よこめぐり」。パッケージ名は `app.yokozurashi.steps`（変えると別のアプリとして入り直すことになるので、そのままにしている）。実装と一緒に、このファイルを正本として書き換えていく。

## 概要

歩数を「きょう何歩」ではなく、旅を始めてからの**累計の距離**として見せるウィジェット。歩いたぶんだけ、よこずらしが日本を西の端（与那国島）から東の端（納沙布岬）へ進む。通った土地ごとに名物があり、よこずらしはそれをずらしながら次の土地へ向かう（那覇にいるあいだは「シーサーをずらしています」）。

ほかの歩数計やスマートウォッチと役割が重ならないよう、目標歩数、消費カロリー、グラフ、通知は入れない。

見本は `assets/preview.png`（`tools/preview.py` が作る。実機の描画そのものではない）。

## 仕様書 1: 画面

ウィジェットは4×2マスが標準で、大きさは変えられる。白地。「よこ」シリーズは白を基調にして、作品ごとにアクセントカラーを持つ。よこめぐりのアクセントカラーは #EE7948。

| 色 | 値 | 使うところ |
| --- | --- | --- |
| アクセント | #EE7948 | 帯の塗り、線の進んだぶん |
| アクセントの濃い色 | #C4501F | 白地にのせる文字（いまの場所）。#EE7948 のままだと白地で読みにくいため |
| アクセントの薄い色 | #FCE4D9 | 絵がまだない都道府県の、仮の丸 |
| 墨 | #141414 | 数字、帯の枠線と文字、線 |
| 灰 | #5A5A5A | 小さな補足の文字 |

寸法は基準寸法250×172dpでの値で、実際の大きさに合わせて全体を拡大・縮小する（0.8〜1.8倍）。横の余りは帯と線が伸びて埋め、縦の余りは帯の上下に半分ずつ入る。

| 要素 | 位置と大きさ（dp） | 見た目 |
| --- | --- | --- |
| いまの場所 | 左16・上の行 | 地点の名前だけ（「那覇」）、13sp太字、アクセントの濃い色。都道府県の名前は、右上の絵の下に出す |
| 累計の距離 | 左16・上31。数字の高さ32 | kmの整数部は手描き数字（タイマーと同じ素材。4と5は黒塗り）。小数1桁と「km」は15spのフォント。絵の左に入らない桁数になったら全体を縮める |
| きょうの歩数 | 距離の下の行 | 「きょう」10sp灰、「6,543歩」13sp、その右に更新マーク（アクセントの薄い色の丸・半径10に、墨のまるい矢印）。最後に読めた時刻は出さない |
| 右上の絵 | 右20・上9、50×50。その下に都道府県の名前 | いまの地点の名物の絵。なければ、いまいる都道府県の標章。どちらもなければ薄い丸。絵の下には、いつも都道府県の名前（10.5sp太字、アクセントの濃い色、絵のまん中にそろえる）を添える。標章と名前をいっしょに覚えられるようにするため |
| 帯 | 左右10・上88、高さ30 | 塗りアクセント、枠線2 墨、角丸14。文は15sp・墨・1行。帯に入る文はそのまま出し、入らない文は右から左へ流す（毎秒40dp、止まらず繰り返す）。文の終わりから次の文の頭までのすきまは約0.8〜1.3秒（32dp＋ベルトの幅の刻みぶん最大20dp）。文字の左右の余白12 |
| 道のりの線 | 左右26、下端から26 | 左端の黒丸がいまの地点、右端の白丸が次の地点。進んだぶんを太いアクセントで塗る |
| よこずらし | 線の上、進んだ割合の位置。枠60×60（本体は高さ約25） | 9コマの横のびアニメ。足元が線に乗る |
| 船 | 船で渡る区間だけ。線の上、進んだ割合の位置。枠56×56 | 依頼者が描いた船の絵（`res/drawable-nodpi/ship.png`、285×285px）。船底を線より5下へ沈める。この区間では、よこずらしを小さく（枠32×32）して前の甲板に乗せ、線を波の形にする。煙突の煙は帯の下の縁に少し重なる |
| 線の下の文字 | 下端 | 左に地点の名前、右に「読谷まで あと11.5km」。船で渡る区間は「船で宮古島まで あと3.2km」。10.5sp灰 |

文字のフォントは Zen Maru Gothic。ウィジェットの文字部品は独自フォントを使えないため、帯の文とよこずらし以外は1枚の画像として描く（`Panel`）。その上に、流れる文（`Belt`）とよこずらしのコマ送りの部品を重ねる。帯の文だけは、流すために文字部品を使うので、端末の標準フォントになる（よこずらしニュースと同じ）。何周目かはウィジェットには出さず、アプリの画面に出す。

### 右上の絵

絵は2段になっている。下の段が都道府県の絵、上の段が名物の絵。都道府県の絵は47枚そろっていて、名物の絵は余裕が出たら地点ごとに足していく。

都道府県の絵には、都道府県の標章（県章）を使っている（0.9）。依頼者が見つけた一覧の画像 `assets/pref_marks.png` から、`tools/make_pref_marks.py` で1つずつ切り出した。白地を透明にして墨の色にしただけで、形には手を加えていない。一覧の1マスは150pxほどなので、大きく出すと輪郭が少しぼやける。標章は各都道府県が使い方の決まりを持っているので、アプリをほかの人に配るときは決まりを確かめる（いまは依頼者の端末だけで使う）。

| 段 | 中身 | ファイル名 | 出るとき |
| --- | --- | --- | --- |
| 下 | 都道府県の標章（県章） | `pref_NN.png` | その都道府県にいるあいだ。ただし、いまの地点に名物の絵があればそちらが出る |
| 上 | その地点の名物 | `meibutsu_NN_M.png` | その地点にいるあいだ（その地点に着いてから、次の地点に着くまで） |

出す絵は、名物の絵 → 都道府県の絵 → 仮の丸（薄い丸）の順に、あるものを選ぶ。どの場合も、絵の下に都道府県の名前を添える。47枚だけのあいだは都道府県の形が出て、あとから名物の絵を置くと、その地点でだけ名物に替わる。

- NN は都道府県の番号（01 北海道〜47 沖縄県）、M は `tools/route.csv` の「絵の番号」
- 背景が透明のPNG。正方形で、600×600px前後。余白は詰める（枠いっぱいに出る）
- `app/src/main/res/drawable-nodpi/` に置いてビルドし直す。ソースの書き換えは要らない。1枚ずつ足していける
- 地点を足したり並べ替えたりしても、絵の番号は変えない（変えると、置いてある絵が別の地点に出る）。足す地点には、その都道府県でまだ使っていない番号を付ける

### 帯の文

そのままやると事故になる文（「合掌造りの屋根をずらしています」）にはしない。よこずらしは、ずれたものを元の状態に戻すか、いい状態になるようにずらす。

- 形は「（何か）を（元の状態・いい状態）にずらしています」
- 例: 「ヨナグニウマを草原のほうにずらしています」「ずれた合掌造りの屋根を元の位置にずらしています」「オスのシーサーをメスのシーサーの所にずらしています」
- 下関だけは別の型で、言葉を一文字ずらす文にしてある（「ふぐを一文字ずらして、ふく（福）にしています....」）。よこずらしは文字も一文字ずらせる。下関ではふぐを「ふく」と呼ぶ
- 文は地点ごとに1つで、`tools/route.csv` の7つめに書く。全部の文は `python3 tools/make_route.py` を実行すると出る
- 文の中に、その地点の名物の名前を入れる（検索の言葉と対応させるため）
- 長さの決まりはない。帯に入らない文は流れる

## 仕様書 2: 旅のしくみ

- 距離は「累計の歩数 × 歩幅」。歩幅は標準70cm、アプリの画面で40〜100cmの範囲を5cmきざみで変えられる。歩幅を変えると、これまでの距離も計算し直す
- 道すじは `tools/route.csv` の378地点。47都道府県をすべて通る。陸の区間の距離は、となり合う2地点の直線距離
- 海をまたぐ26区間（沖縄と鹿児島の島々、天草〜島原、佐賀関〜佐田岬、明石〜淡路島〜神戸、新潟〜佐渡〜村上、横須賀〜鋸南、大間〜函館）は船で渡る扱いにして、実際の距離にかかわらず1区間10kmにする。海の上で同じ文が何週間も続かないようにするため。累計の距離の数字は、歩いたぶんのまま出す
- ゴールの納沙布岬まで8,040km。陸の区間は平均22km（最短8km、最長40km）。1日8,000歩（5.6km）なら、文が変わるのは平均で4日に1回、那覇まで約2週間、九州本土（指宿）まで約2か月、ゴールまで約4年
- ある地点に着いてから次の地点に着くまで、その地点の文を帯に出す
- ゴールに着いたあとは、20km進むと与那国島に戻って2周目が始まる。累計の距離は増えつづける

名物は、食べもの・生きもの・建物・景色を取りまぜた。商品名は避け、一般の呼び名にした。

## 仕様書 3: 歩数の数え方

歩数はヘルスコネクトから読む。0.1 では端末の歩数センサーを直接読んでいたが、実機でうまく取れなかったので 0.2 で替えた。ヘルスコネクトには、歩数計のアプリや時計が書きこんだ歩数が集まっていて、同じ歩みが重なっていても合計は二重に数えない。

使うのは、Android 14 以上の本体に入っているヘルスコネクト（`android.health.connect`）。Android 13 以下で使う別アプリ版のヘルスコネクトは、Jetpack のライブラリが要り、外部ライブラリなしのこの作りでは使えない。そのため、このウィジェットが動くのは Android 14 以上に限る。

読むのは次の2つの合計:

- 締めた時刻から今まで（累計のうち、まだ締めていないぶん）
- きょうの0時から今まで（きょうの歩数）

累計は「締めたぶん」と「まだ締めていないぶん」の足し算にする。きょうと前の2日ぶんは締めず、読むたびに数え直すので、時計があとからまとめて送ってきた歩数も入る。それより前は1日1回、締めて端末に足しこむ。ヘルスコネクトの古いデータが消されても、累計は減らない。

| 読むとき | しくみ |
| --- | --- |
| 約15分ごと | JobScheduler（`StepJob`）。再起動のあとも続く |
| ウィジェットの更新マークを押したとき | `ReloadActivity`。ヘルスコネクトは、裏で読む許可のない端末では画面に出ているアプリにしか歩数を渡さないので、透明な画面を一瞬開いて読む。別のタスクで開き（`taskAffinity` が空）、最近使ったアプリにも出さない |
| アプリの画面を開いたとき、「いま読み直す」を押したとき | `MainActivity` |
| 0時、時刻の変更、再起動、アプリの更新のあと | `DayAlarm`、`SystemEventReceiver` |

必要な許可は2つで、どちらもアプリの画面から求める。

| 許可 | ないとき |
| --- | --- |
| 歩数の読み取り（`READ_STEPS`） | 何も読めない。帯に「タップして歩数の読み取りを許可」 |
| バックグラウンドでの読み取り（`READ_HEALTH_DATA_IN_BACKGROUND`） | アプリの画面を開いているときにしか読めない。15分ごとの読み取りは空振りし、ウィジェットの下半分のタップもアプリを開く。端末によっては、この許可そのものが出ない |

- 旅の出発は、はじめて読もうとした日の0時。その日の朝からの歩数が入る。「旅をやり直す」のあとは、やり直した時刻から
- 歩数は端末の中だけに保存し、通信はしない（インターネットの権限を持たない）
- 歩数が0のままなら、歩数を記録しているアプリや時計が、ヘルスコネクトに歩数を書きこむ設定になっていない

## 仕様書 4: アプリ本体

画面は2枚。メインの画面は日本地図で、これまでにずらしたものを見せる。ほかのことは設定画面にまとめる。見本は `assets/map_mock.png`（0.18 のときに描いた案。実機の画面そのものではない）。

### メインの画面（地図）

| 要素 | 見た目とふるまい |

操作:

- 指で動かす、2本指で広げる・縮める、ダブルタップで拡大
- まとめたピンをタップすると、そこへ寄って拡大する
- 広げられるのは、画面の幅に経度0.4度ほどが入るまで。縮められるのは、日本全体が入るまで

はじめに見せる範囲は、ずらし終わった地点といまの場所がぜんぶ入る範囲（いちばん狭くて緯度2.2度ぶん）。旅が進むほど引いていき、いずれ日本全体が見える。画面を開いたときに進んでいたら、範囲を合わせ直す。

地図のデータは、国土地理院「地球地図日本」（2016）の行政界を、`tools/make_map.py` で都道府県ごとにまとめて簡略化したもの（`res/raw/japan_prefs.bin`、86KB、11,041点）。約2km四方より小さい島は省いている。出典は設定画面に書く。
簡略化は47都道府県をまとめて行い、となり合う県の境が同じ線のままになるようにしている（県ごとに別々に簡略化すると、拡大したときに境が二重に見える）。

線の揺らし方（`MapView.buildShape`）: 描くたびに、県の形の点を画面の上で4dpごとに打ち直し、画面の上の位置で決まる、なめらかなずれ（大きさ1.3dp、波の長さ14dp）でずらす。ずれは位置だけで決まるので、となりの県と共有する境は同じ線になり、指で動かしても形は変わらない。広げたり縮めたりしているあいだは、揺れ方が少しずつ変わる。画面の外の部分は打ち直さない。

### ずらし終わった日

地点を通った日を、周回を通した通し番号ごとに記録する（`PassLog`）。名物 i をずらし終わった日 = 次の地点を通った日。

- まだ日付のない地点があると、歩数を読んだあとに、ヘルスコネクトの日ごとの歩数（出発の日からきょうまで）を読んで割り出す。地点までの道のり÷歩幅の歩数に、日ごとの歩数の合計が届いた日をその地点の日とする
- 一度記録した日付は変えない。途中で歩幅を変えると、それより前の地点の日付と実際とが数日ずれることがある
- 確認用に足した距離で進んだ地点など、歩数が届かない地点はきょうの日付にする
- 「旅をやり直す」で記録を消す

### 設定画面

メインの画面の右上の歯車から開く。置くもの:

- ヘルスコネクトの許可の状態と、許可を求めるボタン、ヘルスコネクトを開くボタン
- 旅のようす（いまの場所、ずらしているもの、次の地点までの残り、累計の距離と歩数、きょうの歩数、出発の日時）と「いま読み直す」ボタン
- 歩幅の設定（−5cm・+5cm）
- 「ホーム画面にウィジェットを追加」ボタン
- 「旅をやり直す」ボタン（確認のうえ、累計を0に戻す）
- 歩数と地図の説明、地図の出典

確認用のしかけ: 設定画面の題名「設定」を長押しすると、30km進む。歩かなくても、地点の切り替わりや帯の文の長さを実機で見られる。「旅をやり直す」で消える。

ヘルスコネクトの許可の画面から開く「このアプリがデータを使う理由」は、設定画面につなぐ。

## 技術構成

よこずらしニュース（`../news-widget`）と同じ作り。Java、Gradleなし、`build.sh`、minSdk 26、外部ライブラリなし。入れることは Android 8 以上でできるが、歩数を読めるのは Android 14 以上。

| ファイル | 役割 |
| --- | --- |
| `HealthSteps` | ヘルスコネクトに、ある期間の歩数の合計と、日ごとの歩数をたずねる |
| `StepReader` | 読んで帳簿を更新する。8秒待って返事が来なければあきらめる |
| `StepStore` | 歩数の帳簿（締めたぶん、締めていないぶん、きょう、歩幅）。SharedPreferences |
| `Route` | 道すじの表。`tools/make_route.py` が `tools/route.csv` から作る |
| `Journey` | 距離から、いまの地点・名物・次の地点までの残りを割り出す |
| `Panel` | ウィジェットの絵を1枚の画像に描く |
| `Belt` | 帯の文。入らない長さなら流す。よこずらしニュースの `NewsBelt` と同じしくみ。ベルトのレイアウトとアニメ（300〜1300dp、20dp刻みの51組）と幅の一覧 `BeltSizes` は `tools/make_belts.py` が作る |
| `StepWidgetProvider` | ウィジェット。よこずらしと帯の文の位置は、ウィジェット全体に対する割合で決める（入れ子の枠の weightSum を変える）。画素の数で決めると、端末が知らせる大きさと実際の大きさが食い違う端末でずれる |
| `StepJob`、`DayAlarm`、`SystemEventReceiver` | 読むきっかけ |
| `MainActivity` | メインの画面（地図と下のカード） |
| `MapView` | 地図を描き、指の操作とピンのタップを受ける。ピンのまとめもここ |
| `JapanMap` | 地図のデータを読み、緯度経度を地図の座標に直す |
| `PassLog` | 地点を通った日の記録と、日ごとの歩数からの割り出し |
| `SettingsActivity` | 設定画面 |
| `ReloadActivity` | ウィジェットの更新マークで開く、見えない画面 |

素材（手描き数字、よこずらし9コマ、Zen Maru Gothic）はニュースウィジェットのものを写した。絵そのものには手を加えていない。
